# M1 exit check: two real installations exchange a ping

The offline tests and the network simulator prove the code agrees with our assumptions about the client. This check proves the client agrees with the code. It is the **exit criterion of milestone M1** and it is **not done yet**: nobody has run it on WoW Forever. Record the result in the table at the end (or in an in-game test issue) and tick the box in [M1-foundations.md](../roadmap/M1-foundations.md).

## What you need

- Two clients on WoW Forever at the same time: two computers, or two accounts on one. Both characters must be able to write in custom channels (if a ping fails, the probe checks S2 and S6 of M0 tell why: low-level and trial characters may be refused, see [docs/spike/README.md](../spike/README.md)).
- The addon installed on both with `tools/install_addon.py` (it copies `AzerothGuildFinder/` into the AddOns folder named in `tools/local.ini`; run `python -I -X utf8 tools/fetch_libs.py` once before, so the libraries are in `AzerothGuildFinder/Libs/`).

## Steps

1. On both clients log in (or `/reload` after installing). Wait about 10 seconds: the addon joins its channel 5 seconds after you enter the world.
2. Type `/gf debug` on each client. In the **Channel** section expect `Channel: AzGuildFinder (number N), ready` and `failures 0`. In the **Transport** section expect `normal` (not `listen-only`).
3. Look at every chat tab: **no** window shows `AzGuildFinder`, no "joined channel" line appeared at login, and `/1` is still General (the channel number N is the last of your channels).
4. On client A type `/gf debug ping`. After 5 seconds expect `1 peer(s) answered. Round trip: shortest ... ms`. Repeat on client B.
5. With a third client (or a friend who has the addon) the count becomes 2.
6. Ping again from A within 10 seconds to see the cooldown message (`Wait a little: one ping every 10 seconds`).

## What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| `Channel: ... not joined`, last problem `limit` | the character is already in the maximum number of channels (the addon printed a warning once) | `/gf debug` and how many channels you have (`/chatlist`) |
| last problem `refused`, `throttled`, `banned` or `timeout` | the server did not let the character join | `/gf debug`, the character level, whether it is a trial account |
| `Transport: listen-only (InvalidChannel)` | the server refuses addon messages in this channel (the case M0 S2 and S6 measure) | `/gf debug` from both clients |
| the channel shows in a chat window, or a join line appears | hiding or filtering failed | which tab, and the line |
| `/1` is not General | moving the channel to the end failed | the output of `/chatlist` |
| `No peer answered` with both clients ready and `normal` | messages leave but are not heard (prefix, channel or protocol problem) | `/gf debug` from both clients |

`/gf debug` never prints player or guild names, so its output is safe to paste.
