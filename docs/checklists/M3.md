# M3.1 own listing and guild sync

The offline tests prove the rules ([test_own_listing.lua](../../Tests/test_own_listing.lua)), including a small simulator scenario with a Guild Master, two members and a client without a guild. They cannot prove that WoW Forever names the Guild Master in the roster and the sender of a `GUILD` addon message the same way. That is what this list checks. The editor arrives with M3.2: until then the development-only commands `/gf debug publish` and `/gf debug delist` stand in for its buttons.

## What you need

- Two clients on WoW Forever at the same time, **in the same guild**: client A is the **Guild Master**, client B a member (not an officer). A third client C in the same guild, an officer, is useful for the last steps. A fourth character without a guild (client D) on the same realm and faction shows the public side; it can be client B after leaving the guild, or skipped.
- A **development build** on every client (`tools/install_addon.py`). Release builds refuse the two debug commands.
- Publishing a listing this way makes the guild **really listed** for every Guild Finder user on the realm and faction. Withdraw it at the end with `/gf debug delist` (or publish your real listing once the editor exists).

## Steps

### Publish and receive

- [ ] On A: `/gf debug publish`. Expect `Listing published. It will reach other players over the next minutes.`
- [ ] On A: `/gf debug` shows in the **Own listing** section `guild copy rev 1 (listed)` and `next publication in ... s`; the **Sync** section counts the `ANN`.
- [ ] On B (online at the time), within a few seconds: `/gf debug` shows `guild copy rev 1 (listed)` and `GLIST ... received 1 (accepted 1, refused 0 ...)`.
- [ ] On A: `/gf debug publish` again at once. Expect `You can publish again in 4:5x (one published change every 5 minutes).` Then `/reload` and try again: the wait keeps counting, it does not start over.
- [ ] After the 5 minutes, on A: `/gf debug publish`. B's `/gf debug` shows `rev 2`.
- [ ] On D (no guild): the guild appears in Find a Guild within a minute (the `ANN` of A, or of a member).

### The roster check (INT-02)

- [ ] Log B out, publish nothing, log B in again: about 3–10 s after login B sends a `GLREQ` (`GLREQ sent 1` in its `/gf debug`) and, if A is online, A answers (`answered 1` on A). B shows the same `rev` as A.
- [ ] Log B in **before** the roster is loaded (right after the loading screen) while A publishes: if the `GLIST` arrives first, `waited for roster 1` appears and the copy is still accepted a moment later.
- [ ] **Record**: does a member's `/gf debug` ever show `refused 1` after a publication of the real Guild Master? It must not. If it does, the name of the sender of a `GUILD` addon message and the name in the roster differ (for example the realm suffix): send the `/gf debug` output of both clients.
- [ ] A forged `GLIST` cannot be sent without editing the addon; the offline tests cover that case. Skip it in game.

### Change of Guild Master

- [ ] With C (officer) online: A promotes C to Guild Master in the game. On A, `/gf debug publish` now says `You are no longer the Guild Master: the change was not saved.` On C, `/gf debug publish` works at once (the 5-minute limit belongs to each character, and C has never published) and publishes the next `rev`, with the same listing as before; B's copy follows; B's `/gf debug` shows the same `rev` as C.
- [ ] Give the guild back to A afterwards (or keep going with C as the Guild Master).

### Withdraw

- [ ] On the Guild Master: `/gf debug delist`. Expect `Your guild was removed from Guild Finder.`; its `/gf debug` shows `guild copy rev N (withdrawn)`; B shows the same within a few seconds.
- [ ] On D: the guild disappears from Find a Guild (it may stay if D only learned about the guild from a client that has not announced it since D's last `/reload`: see INT-05 in SPEC-02 §8).
- [ ] No Lua error appeared during any of the above (`/console scriptErrors 1`).

## What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| `only work in development builds` | the installed copy is a packaged release | how the addon was installed |
| B: `received 0` | the `GLIST` did not arrive over `GUILD` | `/gf debug` from A and B (Transport section) |
| B: `refused 1` after a real publication | the roster and the message disagree about the Guild Master's name | `/gf debug` from A and B, whether both are on the same realm |
| B: `waited for roster` keeps growing, no copy | the roster never names a rank 0 member | `/gf debug` from B |
| D never sees the guild | the `ANN` did not reach the channel | `/gf debug` from A and D (Sync section) |
