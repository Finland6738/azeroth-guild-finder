# M3 milestone check: summary and order of the in-game run

Milestone M3 (Listings) is **in progress**. The steps below are done offline and **waiting for the owner's in-game check**. Nobody has run the M3 code in the real WoW Forever client, so nothing below the "In game" heading is verified. Each step of M3 adds its list here; M3.8 adds the exit check and the offline results of the whole milestone.

## In game (waiting for the owner)

Setup: `python -I -X utf8 tools/fetch_libs.py` once, then `python -I -X utf8 tools/install_addon.py` (a development build, `Config.DEV` true). In game, `/console scriptErrors 1` first so Lua errors show up. Report problems with `/gf debug` output (it never prints player or guild names).

|---|---|---|---|---|

# M3.1 own listing and guild sync

The offline tests prove the rules ([test_own_listing.lua](../../Tests/test_own_listing.lua)), including a small simulator scenario with a Guild Master, two members and a client without a guild. They cannot prove that WoW Forever names the Guild Master in the roster and the sender of a `GUILD` addon message the same way. That is what this list checks. The editor arrives with M3.2: until then the development-only commands `/gf debug publish` and `/gf debug delist` stand in for its buttons.

## What you need

- Two clients on WoW Forever at the same time, **in the same guild**: client A is the **Guild Master**, client B a member (not an officer). A third client C in the same guild, an officer, is useful for the last steps. A fourth character without a guild (client D) on the same realm and faction shows the public side; it can be client B after leaving the guild, or skipped.
- A **development build** on every client (`tools/install_addon.py`). Release builds refuse the two debug commands.
- Publishing a listing this way makes the guild **really listed** for every Guild Finder user on the realm and faction. Withdraw it at the end with `/gf debug delist` (or publish your real listing once the editor exists).

## Steps

### Publish and receive

- [ ] On A: `/gf debug publish`. Expect `Listing published. It will reach other players over the next minutes.`
- [ ] On A: `/gf debug` shows in the **Own listing** section `guild copy rev 1 (listed)` and `next publication in ... s`; the **Sync** section counts the `ANN`.
- [ ] On B (online at the time), within a few seconds: `/gf debug` shows `guild copy rev 1 (listed)` and `GLIST ... received 1 (accepted 1, refused 0 ...)`.
- [ ] On A: `/gf debug publish` again at once. Expect `You can publish again in 4:5x (one published change every 5 minutes).` Then `/reload` and try again: the wait keeps counting, it does not start over.
- [ ] After the 5 minutes, on A: `/gf debug publish`. B's `/gf debug` shows `rev 2`.
- [ ] On D (no guild): the guild appears in Find a Guild within a minute (the `ANN` of A, or of a member).

### The roster check (INT-02)

- [ ] Log B out, publish nothing, log B in again: about 3–10 s after login B sends a `GLREQ` (`GLREQ sent 1` in its `/gf debug`) and, if A is online, A answers (`answered 1` on A). B shows the same `rev` as A.
- [ ] Log B in **before** the roster is loaded (right after the loading screen) while A publishes: if the `GLIST` arrives first, `waited for roster 1` appears and the copy is still accepted a moment later.
- [ ] **Record**: does a member's `/gf debug` ever show `refused 1` after a publication of the real Guild Master? It must not. If it does, the name of the sender of a `GUILD` addon message and the name in the roster differ (for example the realm suffix): send the `/gf debug` output of both clients.
- [ ] A forged `GLIST` cannot be sent without editing the addon; the offline tests cover that case. Skip it in game.

### Change of Guild Master

- [ ] With C (officer) online: A promotes C to Guild Master in the game. On A, `/gf debug publish` now says `You are no longer the Guild Master: the change was not saved.` On C, `/gf debug publish` works at once (the 5-minute limit belongs to each character, and C has never published) and publishes the next `rev`, with the same listing as before; B's copy follows; B's `/gf debug` shows the same `rev` as C.
- [ ] Give the guild back to A afterwards (or keep going with C as the Guild Master).

### Withdraw

- [ ] On the Guild Master: `/gf debug delist`. Expect `Your guild was removed from Guild Finder.`; its `/gf debug` shows `guild copy rev N (withdrawn)`; B shows the same within a few seconds.
- [ ] On D: the guild disappears from Find a Guild (it may stay if D only learned about the guild from a client that has not announced it since D's last `/reload`: see INT-05 in SPEC-02 §8).
- [ ] No Lua error appeared during any of the above (`/console scriptErrors 1`).

## What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| `only work in development builds` | the installed copy is a packaged release | how the addon was installed |
| B: `received 0` | the `GLIST` did not arrive over `GUILD` | `/gf debug` from A and B (Transport section) |
| B: `refused 1` after a real publication | the roster and the message disagree about the Guild Master's name | `/gf debug` from A and B, whether both are on the same realm |
| B: `waited for roster` keeps growing, no copy | the roster never names a rank 0 member | `/gf debug` from B |
| D never sees the guild | the `ANN` did not reach the channel | `/gf debug` from A and D (Sync section) |

## Result

| Date | Clients | Publish → member | Limit after /reload | GLREQ at login | GM change | Delist | Notes |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

# M3.2 editor shell and checklist

The offline tests prove the rules ([test_editor_model.lua](../../Tests/test_editor_model.lua), [test_ui_editor.lua](../../Tests/test_ui_editor.lua)): the nine checklist items, the status of the seven steps, the reasons **Publish listing** is off, the stepper, the draft, Discard changes and Delist. They cannot show how it **looks** in the client or prove that the game reports the Guild Master the way the editor expects. The steps themselves (Identity to Contact) arrive with M3.3 to M3.6: until then each step page says that it arrives in a later version, and a development build has **Fill with sample values** on the last step (it fills every field with sample values, including a made-up emblem) so that the checklist and the main button can be tried. `/gf debug editor` opens the editor on a listing that is already out, until My Guild has its Edit button (M3.8).

## What you need

- One client on WoW Forever, a **development build** (`tools/install_addon.py`), with a character that is the **Guild Master** of a guild that has **no listing** (or withdraw it first with `/gf debug delist`). A second character in the same guild that is **not** the Guild Master is useful for the last steps.
- Publishing makes the guild **really listed** for every Guild Finder user on the realm and faction. Withdraw it at the end (`/gf debug delist`).

## Steps

### Opening and the stepper

- [ ] As the Guild Master of a guild with no listing, `/gf`: the window opens on **Create Listing** with the title *Identity* and *STEP 1 OF 7*. The left page shows *Listing sections*, seven numbered steps, the draft line, a grey **Publish listing** button with a reason under it and no Delist button. **Look**: compare with [mockup 03](../specs/mockups/img/clean/03-listing-editor.webp) and [08](../specs/mockups/img/clean/08-editor-activity.webp); note what differs.
- [ ] Click each step, and use **Next** and **Back** in the title bar: the title and *STEP n OF 7* follow, the active step is highlighted, **Back** is grey on step 1 and **Next** on step 7. Steps 1 to 6 show a short "arrives in a later version" card; the right column (live preview, checklist, guild name) stays on all six and gives way to the full card and the checklist on step 7.
- [ ] The text fits: no text runs out of its card or over a neighbour, in particular the reason under the red button (260 px wide), the checklist rows and the step names. Try the window at 60 % and 140 % (`/gf scale 60`, `/gf scale 140`).
- [ ] The live preview card (right column) shows your guild's name, and the guild name card says *Guild name: ...* with the explanation. Step 7 shows the same card as in Find a Guild (banner, emblem shield, tags).

### The checklist and the draft

- [ ] On step 7, click **Fill with sample values**. Every step turns green (*7 / 7 ready*), the checklist is all green, the card shows the sample subtitle, and the note under it says *Everything is ready...*. The button **Publish listing** turns red.
- [ ] In the checklist (right column, or step 7), click an item: the editor goes to the step named in *Fix "..."*. Click *You are the Guild Master*: nothing happens (it has no step).
- [ ] `/reload`, then `/gf`: the sample values are still there (the draft) and so is the step you were on if the window stayed open. Close the window with Esc and open it again: still there.
- [ ] **Discard changes**: it asks first; **Cancel** keeps everything; **Discard changes** empties the editor again (*2 / 7 ready*) and shows *Changes discarded.*

### Publish, Save changes, Delist and the limit

- [ ] Fill with sample values again. Press **Publish listing**: *Listing published. It will reach other players over the next minutes.* and the tabs become **My Guild** and **Applications** (the editor is gone). A second client without a guild sees the guild in Find a Guild within a minute.
- [ ] `/gf debug editor`: the editor opens on the listing. The button now says **Save changes** and is grey with *Nothing has changed since the last published version.* A **Delist** button shows. (Changing a field and saving it cannot be tried in game until the steps of M3.3 to M3.5 exist; it is covered offline.)
- [ ] Press **Delist**: it asks (*Remove your guild from Guild Finder? Pending applications will be closed.*); **Cancel** does nothing; **Delist** removes the listing (*Your guild was removed from Guild Finder.*), the tab goes back to **Create Listing** and the editor is filled with the last listing.
- [ ] Right after the withdrawal the main button is grey with *You can publish again in 4:5x ...* and the time goes down while the page is open; after five minutes it turns red and publishing works again.

### The Guild Master check

- [ ] With the second character (a member or an officer): `/gf` does **not** show **Create Listing**. `/gf debug editor` there (a development build) opens the page covered by *Only the Guild Master can create or edit the listing.*, and nothing is saved.
- [ ] While the editor is open on the Guild Master, have the Guild Master rank given to somebody else: the editor's button turns grey with *You are no longer the Guild Master...* (the tab also disappears at the next `GUILD_RANKS_UPDATE`). **Record** how long that took after the change.
- [ ] No Lua error appeared during any of the above (`/console scriptErrors 1`).

## What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| a step's text or the reason under the button is cut off or overlaps | a layout size is wrong | a screenshot, the window scale, `/gf debug` Interface section |
| the button is grey although every item is green | a reason that is not shown, or the clock | what the line under the button says, `/gf debug` Own listing section |
| the draft is gone after `/reload` | the saved data was not written | `/gf debug` (Own listing and Config sections) |
| Publish is red but nothing is published | `IsGuildLeader()` disagrees with the roster | `/gf debug` from the Guild Master |
| **Create Listing** shows for a character that is not the Guild Master | the role is wrong | `/gf debug` Role section |

## Result

| Date | Client | Look matches mockups | Draft after /reload | Publish and limit | Delist | GM check | Notes |
|---|---|---|---|---|---|---|---|

# M3.3 identity and about steps

The offline tests prove the limits, the counters and the language rules ([test_editor_steps.lua](../../Tests/test_editor_steps.lua)). They run on a mock client, so they cannot prove how the real client's multi-line edit box, its menus and its textures behave. That is what this list checks.

## What you need

- One client on WoW Forever, a **development build**, with a character that is the **Guild Master** of a guild that has **no listing** (as for M3.2). Nothing is published by this list.
- `/console scriptErrors 1`, so that Lua errors show up.

## Steps

### Identity

- [ ] `/gf`, step **Identity**: the **Guild name** card shows your guild's name, with a lock icon, and the tooltip says to rename the guild in game. There is no way to type into it.
- [ ] Click the **Subtitle** box and type: the text shows, the counter goes up (*n / 60*) and the live preview on the right shows the subtitle at once. Paste more than 60 characters: the text is cut at 60. Paste text with a line break: the break is dropped.
- [ ] Clear the box with the x button or by selecting all and deleting: the counter goes back to *0 / 60* and the preview line is empty. The *Subtitle* item of the checklist turns red-empty again.
- [ ] **Banner**: the gallery shows the **Default** tile (highlighted) and, until the fileIDs are confirmed, the note that no pictures are available. If you filled `Assets.BANNERS` with candidates: each shows a picture cropped sensibly, a click highlights it and the live preview card shows it; **Default** takes it away. **Record** the fileIDs that load and tick the second in-game box of M3.3 in the roadmap.
- [ ] `/reload`, then `/gf`: the subtitle (and banner) you chose are still there.

### About

- [ ] Step **About**: click inside the big box and type. The text wraps, the counters read *n / 500* and *n / 12 lines*, the grey hint says *Write at least 30 characters to publish.* until 30 characters and then goes.
- [ ] Press Enter eleven times: the counter reaches *12 / 12 lines*; the thirteenth line is refused (a twelfth Enter does nothing). Paste a text of more than 500 characters: it is cut at 500. Paste a text with 20 lines: it is cut at 12 lines.
- [ ] Click outside the text itself but inside the box: the box takes the focus (gold ring). Esc leaves it. Typing never moves the box or draws outside it; with 12 long lines the text stays inside.
- [ ] Type a `|` in the text: it works, and the counter counts it twice.
- [ ] **Main language**: open the menu, pick *Italian*: the box shows it, the checklist item *Main language* turns green and the preview card shows the language tag.
- [ ] **Also spoken**: it was grey until the main language was picked. Open it: *Italian* is not in the list. Pick *English* and *German*: the box shows both. Now change the main language to *German*: *German* leaves the list, *English* stays selected, *Italian* is gone (it was the old main one).
- [ ] Open a menu and click outside it: it closes. Open one and press Esc or change step: it does not stay on screen.
- [ ] On step 7 **Fill with sample values**, then go back to Identity and About: the fields show the sample values. **Discard changes**: they empty.
- [ ] The text fits at 60 %, 100 % and 140 % window scale (`/gf scale 60`, `/gf scale 140`): nothing runs out of a card.
- [ ] No Lua error appeared during any of the above.

| the text runs outside the description box | the box has no size limit in this client | a screenshot and the window scale |
| a banner tile is empty or black | the fileID does not load or the crop is wrong | its index and fileID |
| a menu stays open or covers the next field | the menu's catcher frame is not on top | a screenshot |

# M3.4 activity step

The offline tests prove the rules ([test_editor_activity.lua](../../Tests/test_editor_activity.lua)): the commitment, the limit of three activities with their order and numbers, and the conversion of the days and the time window to UTC (across daylight-saving time and midnight, as a round trip with the conversion the Find a Guild list uses). They run on a mock client, so they cannot show how the page **looks** in the real one or what your computer reports as its time zone. That is what this list checks.

## What you need

- One client on WoW Forever, a **development build**, with the **Guild Master** of a guild that has **no listing** (as for M3.2). Nothing is published by this list.
- `/console scriptErrors 1`. Know your computer's time zone (its offset from UTC now).

## Steps

### Commitment

- [ ] `/gf`, step **Activity**: the **Commitment** card has three buttons (Casual, Softcore, Hardcore) and, under them, *Choose how committed the guild is.* Click one: it turns dark, the text under it explains it, the hover tooltip of each button says the same, and the live preview card shows the commitment. The *Commitment* item of the checklist turns green.
- [ ] The longest explanation (Hardcore) fits under the buttons without running out of the card.

### Activities

- [ ] The **Activities** card shows 13 chips that wrap into rows, *0 / 3* at the top right and the hint under them. Click *World PvP*, then *Raids*, then *Battlegrounds*: they show **1**, **2**, **3** in the order you clicked, the counter reads *3 / 3* and turns to the warning colour, and the live preview shows the three in that order.
- [ ] With three picked, every other chip is dimmed; hover one: the tooltip says *Up to 3 activities: remove one to pick another*. Clicking it does nothing.
- [ ] Click *World PvP* (number 1) again: it is removed, *Raids* becomes **1** and *Battlegrounds* **2**, and the other chips light up again. Remove all of them: the item *1 to 3 activities* goes back to empty.
- [ ] The chips do not run outside the card at 60 %, 100 % and 140 % window scale (`/gf scale 60`, `/gf scale 140`).

### Days and time

- [ ] Click days (M T W T F S S): the squares turn dark; the tooltip names the day.
- [ ] Open **From** and pick *20:00*: the box shows it, the line under says to pick both a start and an end. Open **To**: *20:00* is not in the list. Pick *23:30*: the line now reads *Players see it in their own time zone · hh:mm–hh:mm UTC*. **Check the UTC numbers against your time zone**: for example in Italy in winter 20:00–23:30 must read 19:00–22:30 UTC, in summer 18:00–21:30 UTC. Record your zone and what it showed.
- [ ] Pick *00:30* to *02:00* with only Monday on, then look at the UTC line: the times are the evening before. Go to another step and come back: the page still shows Monday and 00:30–02:00 (local), not the UTC values.
- [ ] Turn **All day** on: the two menus grey out. Turn it off: they are empty again.
- [ ] `/reload`, then `/gf`: commitment, activities, days and times are all still there.
- [ ] **Discard changes**: the page empties completely (no button left selected, *0 / 3*).
- [ ] The whole page fits in the window without being cut at the bottom (three cards). **Record** if it does not.
- [ ] No Lua error appeared during any of the above.

# M3.5 recruitment, requirements and contact steps

The offline tests prove the rules ([test_editor_recruit.lua](../../Tests/test_editor_recruit.lua)): the class × role grid and the `want` map it makes (Tank 1, Healer 2, Melee 4, Ranged 8, class 0 for any class), the faction filter and the impossible pairs, the status, the limits of the level, the item level and the note, the Discord box (codes, whole links, junk) and the contacts (at most three, only roster members, a contact who left the guild). They run on a mock client, so they cannot show how the pages **look** in the real one, how the slider drags, or how WoW Forever names the members of the roster. That is what this list checks.

## What you need

- One client on WoW Forever, a **development build**, with the **Guild Master** of a guild that has **no listing** (as for M3.2). At least two other characters in the guild, one of them online, make the contact checks possible. Nothing is published by this list.
- `/console scriptErrors 1`. Know your faction.

## Steps

### Recruitment (step 4)

- [ ] `/gf`, step **Recruitment**: the status buttons (*Open to all*, *Selected classes*, *Closed*), the **Looking for** card with a row *Any class* and one row per class of **your faction** (no Paladin in a Horde guild, no Shaman in an Alliance one), four role columns with their round badges, and the two switches. **Look**: compare with [mockup 03](../specs/mockups/img/clean/03-listing-editor.webp); note what differs.
- [ ] Hover a dimmed cell (for example Warrior · Healer): the tooltip says the class cannot play the role, and a click does nothing. Click a possible cell: it turns dark with a check, the count at the top right of the card moves (*1 chosen*), the status becomes *Selected classes*, the *Looking for* item of the checklist and the step turn green. Click it again: it clears and the item goes back to empty.
- [ ] Click a class **name**: every role the class can play is ticked; a second click clears them. *Any class* ticks all four.
- [ ] Choose **Open to all**: *Any class* is ticked for every role. Choose **Closed**: the grid is cleared and greyed out, clicks do nothing, the card says that recruitment is closed, and the checklist item is green. Choose **Selected classes** again: the grid you had comes back.
- [ ] **New player friendly** is off at first, **Accept applications through the addon** is on at first; click each and check the switch moves and the page keeps it after you change step and come back.
- [ ] The whole page fits the window (three cards) without being cut at the bottom. **Record** if it does not.

### Requirements (step 5)

- [ ] The **Minimum level** slider drags smoothly from 1 to the highest level of the game (the number at the right end), the value at the top right follows (*Level 30+*, or *No minimum* at 1).
- [ ] **Minimum item level**: the switch opens a box; type letters (they are dropped) and digits (*250*); clear the box or switch off: the requirement goes away. A value above 999 cannot be typed (three digits at most).
- [ ] **Note**: type a sentence; the counter moves (*n / 120*); paste more than 120 characters: it is cut at 120.
- [ ] Go to another step and come back, then `/reload` and `/gf`: the level, the item level and the note are still there. **Discard changes** empties all three.

### Contact (step 6)

- [ ] The **Discord** card shows `https://discord.gg/` in front of a box for the code. Type `aurora-it`: the line under it says *Invite code: aurora-it*, the checklist item is green. Paste `https://discord.gg/aurora-it` or `https://discord.com/invite/aurora-it?event=1`: the box shows only `aurora-it`.
- [ ] Type `a`, then `https://example.com/x`, then `no!`: each gives its own red explanation under the box, the *Discord code valid* item of the checklist and the step turn red. Clear the box: the step goes back to *optional*.
- [ ] **Characters to contact**: with the box empty the list offers up to five members who are **online**, in the colour of their class, with their level. Type the first letters of a guildmate's name (also without accents or capitals): the list narrows, offline members included. Click one, or press Enter: it joins the list above with its class icon.
- [ ] Pick three. The box disappears and the card says *Up to 3 contacts: remove one to add another*. The **x** of a row removes it and the box comes back.
- [ ] **Record** how the roster writes the names: with or without the realm (`Name-Realm`)? In the list the realm is hidden, and the whisper from a guild page uses the stored name.
- [ ] Have one of the chosen characters leave the guild (or kick it) while the page is open: within a moment (or after `/reload`) its row says *no longer in the guild* in red; it is not removed on its own. Remove it by hand.
- [ ] Open the page right after the login, before the roster is loaded: the card says *Loading the guild roster...* and fills in by itself a moment later. No contact is marked as gone while it loads.
- [ ] `/reload`, then `/gf`: the code and the contacts are still there. **Discard changes** empties both.
- [ ] On step 7, with every other step filled in (the sample button of a development build fills in the rest), check the card shows what you chose and **Publish listing** turns red.
- [ ] No Lua error appeared during any of the above.

# M3.6 emblems

The offline tests prove the rules ([test_emblems.lua](../../Tests/test_emblems.lua), [test_editor_emblem.lua](../../Tests/test_editor_emblem.lua)): the emblem travels as catalogue indices and RGB colours, every client computes the same layers and pixels, malformed input is refused, unknown pieces fall back. They cannot show what the game draws. The list of tabard pieces in [`Data/TabardParts.lua`](../../AzerothGuildFinder/Data/TabardParts.lua) is **provisional**: it waits for the M0 probe (`/agfp tabard`, then `/agfp export tabard`, check S8 of [docs/spike/README.md](../spike/README.md)). This list checks the drawing and collects what M0.7 needs to confirm or replace the provisional values.

## What you need

- Client A: a **Guild Master** of a guild **with a tabard**. Client B: a character in a guild **without** a tabard, or no guild (it can be a Guild Master of a second guild for the designer part), or client A after the tabard part.
- A second client C on the same realm and faction (any character) to see the published emblems from outside. It can be B.
- A development build on every client; `/console scriptErrors 1`.

## Steps

### The tabard pieces (for M0.7)

- [ ] If not done yet: the M0.5 probe on A, `/agfp tabard`, then `/agfp export tabard`, and send the export. It fills in the emblem fileIDs, the emblem count, the border styles and the colour lists of `Data/TabardParts.lua`.
- [ ] On A: `/gf debug`, section **Emblems**: **record** whether it says `sheet loads` or `sheet missing`. `missing` means `Interface\GuildFrame\GuildEmblemsLG_01` does not exist on Forever: the designer then offers only Guild Finder's own symbols.
- [ ] On A: `/dump C_GuildInfo.GetGuildTabardInfo("player")`. **Record** the field names (are `backgroundColor`, `borderColor`, `emblemColor`, `emblemStyle`, `emblemFileID` there? is there a border style?). Do not paste any name.

### The guild tabard (client A)

- [ ] `/gf`, Create Listing, step 1 **Identity**: the **Emblem** card shows a shield at 96 px, **Guild tabard** chosen, *Copied from your guild tabard.* **Look**: does the emblem match the tabard in the game (emblem, its colour, background colour, border colour)? Note what differs; the border **style** is Guild Finder's own *Solid* until M0.7 says how to read the tabard's.
- [ ] `/reload` and open the step right away: if the card says *Reading your guild tabard...*, it must fill in by itself within a few seconds. **Record** whether `GUILDTABARD_UPDATE` came at login or not (the card changes on its own).
- [ ] Change the tabard at a tabard vendor (this costs gold in the game: skip it if you prefer) while the step is open, or before opening it: the card says *Your tabard changed: update the emblem?*; nothing changes until **Update emblem** is clicked.
- [ ] Guild Finder never changed the tabard: it is in the game exactly as you left it.

### The designer (client A or B)

- [ ] Click **Custom emblem**: the designer covers the step page. **Look**: compare with [mockup 07](../specs/mockups/img/clean/07-emblem-designer.webp) (the banner thumbnails of the mockup are not on this page); note what differs. Every part fits inside the page at 60 %, 100 % and 140 % window scale (`/gf scale`).
- [ ] Background, border and emblem colours: each click changes the big preview, the 96 px shield of the card (after **Done**) and the preview card on the right.
- [ ] Border arrows: six styles go round (*Solid*, *Thin*, *Double*, *Studded*, *Bold*, *Notched*).
- [ ] Emblem pages: the arrows turn the pages; **record** the number of pages and whether any tile shows **?** or an empty cell (a game emblem that does not exist: the count of `Data/TabardParts.lua` is too high), and whether the game's emblems look like the tabard vendor's.
- [ ] **Random** a few times: always readable, never the same colour for the emblem and the background. **Reset**: back to the tabard's pieces (A) or to the default crown (B without tabard and without a published listing).
- [ ] **Done**, change step and come back, `/reload`: the design is still there (the draft).

### Seen by others (client C)

- [ ] Publish the listing on A (the 5-minute limit applies). On C, in Find a Guild: the card shows the same emblem (84 px), the guild page shows it at 150 px. **Look**: identical to what A sees, colours included.
- [ ] A card of a guild without an emblem (an old test listing, or `/gf debug seed` in a development build) shows the plain blue shield with the initial in gold.
- [ ] No Lua error appeared during any of the above.

## What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| the tabard emblem differs from the game's | `emblemStyle` is not the index of the emblem sheet, or the colours are read wrong | `/dump C_GuildInfo.GetGuildTabardInfo("player")` without names, a screenshot of both |
| the card stays on *Reading your guild tabard...* | `GetGuildTabardInfo` answers nothing and `GUILDTABARD_UPDATE` never comes | `/gf debug` (Emblems section), whether the guild has a tabard |
| the designer offers only 8 symbols | the emblem sheet is missing on Forever | `/gf debug` (Emblems section) |
| tiles show **?** or empty cells | the provisional emblem count is too high, or a fileID is wrong | the page numbers where it starts |
| the emblem looks different on another client | the rendering differs between clients (it must not) | screenshots of both, the window scale of each |
| the frame, the gloss or the border look wrong at some size | a texture or a size of `Media/` is off | a screenshot and the size (card, page, editor) |
