# M5 in-game checks

Milestone M5 (Release) is not finished: this file collects the checks that only the real WoW Forever client can answer, one list per step, added as the steps are done. Nothing below has been run in the game.

## M5.1 — Settings page

Offline, the options, their defaults, their persistence across a reload and their effects are covered by `Tests/test_settings.lua`. What is left is how it looks and behaves in the real client. One character is enough; a Guild Master or an officer is needed for the Notifications card.

### Steps

- [ ] `/gf`, **Settings** (the first tab of the rail): the Window, Privacy and (for the Guild Master and officers) Notifications cards fit the page at 100 %, 60 % and 140 %, with no text cut or overlapping.
- [ ] Open the game's own settings (*Esc → Options → AddOns*): there is a **Guild Finder** entry showing the same cards. If the entry is **missing**, note it (`/gf debug`, Settings line: `game panel: unavailable`); that is allowed, the Settings tab must then have everything.
- [ ] Defaults on a fresh character (or after deleting the saved variables): minimap button on, notification icon on, *Only when something is pending* off, sound on, share alt count on, window size 100 %.
- [ ] *Show minimap button*: turning it off hides the button at once; `/gf` still opens the window; `/reload` keeps it hidden; turning it back on shows it again, also on another character of the account.
- [ ] *Window size*: each of 60, 80, 100, 120 and 140 % resizes the window at once; `/gf scale 80` moves the control; it is kept after `/reload`.
- [ ] *Share anonymous alt count*: off, then `/gf debug` Stats says sharing is off; on again.
- [ ] Guild Master or officer: *Notification icon on screen*, *Only when something is pending* and *Sound on new application* show and hide the icon, hide it while nothing is pending, and silence the sound; the same switches on the Applications tab and in the icon's right-click menu follow, and the Settings page follows them when changed there.
- [ ] A member or a player without a guild does not see the Notifications card.
- [ ] Drag the window and the notification icon away, then **Reset window position**: both come back; the options are unchanged.
- [ ] If the game's panel exists: change an option in the panel while the window's Settings tab is open (and the other way round): the other follows at once; the panel's **Defaults** button restores the options and the positions. Chat shows no Lua error.
- [ ] Every option is kept after `/reload` and after logging out and in.

If it works, tick the *In game* box of M5.1 in [M5-release.md](../roadmap/M5-release.md).

### What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| no Guild Finder entry in the game's settings | the client has no `Settings.RegisterCanvasLayoutCategory`, or registering raised | `/gf debug` (Settings line) and the Lua error, if any |
| the panel is empty or cut | the canvas size differs from the one assumed (540 x 640) | a screenshot, the window size of the game |
| an option does not stick | the saved value is repaired at login | `/gf debug` (Saved data section) |
| an option has no effect | the module that applies it did not run | the option, `/gf debug` |

## M5.2 — Visual polish and accessibility

Offline, `Tests/test_ui_polish.lua` and `tools/check_addon.py` cover: no text under 12 px at scale 1.0, the WCAG contrast of every text/background pair of the design tokens, a tooltip on every control without a label, Esc and Backspace (never while a text box has the keyboard), the saved positions clamped onto the screen and the window fitting 1280 × 720 at every scale, and the shape of the committed textures. What no test can answer is how it **looks** in the real client. Compare the window with the design system ([00-design-system](../specs/mockups/img/clean/00-design-system.webp), and the other mockups of the same folder) side by side. One character per role is best (a player without a guild, a member, an officer, a Guild Master); `/gf debug gallery` (development builds) shows one of every widget.

### Steps

- [ ] **Full visual comparison with the design system**, at 100 %: parchment pages with a light grain (no visible tiles or seams), the page gutter, the left page darker than the right, the gold round close button, the metal rail with the active tab sticking out and gold-edged. Note every difference you see.
- [ ] **Pills and buttons**: red, parchment, blue (Discord) and grey buttons have a **gloss that spans the whole width** (it used to cover only the left half), rounded ends without a seam where the middle stretches, and a soft shadow.
- [ ] **Shadows**: the window, the cards, the plates and the tabs have a soft brown shadow with no hard edge or square corner at any size; at 140 % it still has no visible seam.
- [ ] **Nine-slice**: cards, chips, fields and tags keep their rounded corners crisp at 60 %, 100 % and 140 %, with no stretched or doubled corner.
- [ ] **Text size**: every text is readable at 100 % and none looks smaller than the status bar text (12 px). Check the rail labels, tags, badges, the day squares and the hints under fields.
- [ ] **Contrast**: the grey secondary text (counters, hints, the line under the brand) is readable on the left page and on cards; green, amber and red text (ready, warnings, errors) are readable on parchment; the dropdown's chosen row is readable; tooltips show their "not allowed" line in a light red.
- [ ] **Tooltips**: hover every icon-only control (the round close buttons, the filter reset, the field *clear* and *copy* buttons, the remove buttons in the contacts list, the emblem swatches and tiles, the rail tabs). Each shows what it does.
- [ ] **1280 × 720** (windowed or a smaller resolution): at every size from 60 % to 140 % the whole book, the rail and the gold close button stay on the screen. Drag the window to the edge, change the resolution, `/reload`: it is back inside the screen. The notification icon too (Guild Master or officer).
- [ ] **Esc**: closes the window; with the cursor in the search box, the first press leaves the box, the second closes. **Backspace** on a guild page goes back to the list; in the search box it deletes a character and does not leave the page. Chat shows no Lua error.

If it all works, tick the *In game* box of M5.2 in [M5-release.md](../roadmap/M5-release.md).

### What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| a button's gloss stops in the middle or has a hard edge | a texture was not loaded or stretches wrongly | a screenshot at 100 % and 140 %, `/gf debug` (Interface section) |
| a square or hard edge around a shadow | the shadow texture is clipped | a screenshot |
| text that is too small or too faint | a style or a colour is not what the audit assumes | a screenshot and the page name |
| the window or the rail partly off the screen | the screen size the client reports differs from what the clamp assumes | the resolution, the UI scale setting, a screenshot |
| Backspace leaves the page while typing | the text box does not report the keyboard focus | the page and the box |

## M5.4 — Diagnostics

Offline, `Tests/test_diagnostics.lua` covers the report sections, the absence of player and guild names, the error ring buffer and the copy box on the mock client. What is left is the real client: the clipboard, the keyboard focus and the real error handler.

### Steps

- [ ] `/gf debug` opens the **Diagnostics** box in the middle of the screen, with the report selected, and the *Ctrl+C to copy* hint shows. The text is readable, not cut, and the box fits at 1280 × 720.
- [ ] **Select all** selects the whole text (also what is below the visible part); Ctrl+C then paste in a text editor or in chat gives the full report. Typing in the box changes nothing. The mouse wheel scrolls it.
- [ ] Esc closes the box (with the cursor in the text, the first Esc leaves the text, the second closes). The **Close** button too. The box can be dragged.
- [ ] The report has the sections *Listen-only*, *Last errors*, *Compat*, *Catalog*, *Sync*, *Role* and *Settings*. The versions at the top match the AddOns list and the client. Read it once: **no character, player or guild name** anywhere (the realm and the character are not there either). If you see one, report it as a bug.
- [ ] If a Lua error of Guild Finder shows up while you test (there is no safe way to cause one on purpose), `/gf debug` lists it in *Last errors* with a path starting at `AzerothGuildFinder/` and no folder of your PC. Errors of other addons are not listed.
- [ ] Paste the report in the Bug report form's last field on GitHub: it is accepted and readable.
- [ ] Chat shows no Lua error while doing all of this.

If it works, tick the *In game* box of M5.4 in [M5-release.md](../roadmap/M5-release.md).

### What to report if it does not work

| Symptom | What it means | What to send |
|---|---|---|
| the box does not open | the box frame raised while it was built | the Lua error |
| Ctrl+C copies nothing | the edit box did not keep the selection | the game build, what you clicked |
| the text is cut or does not scroll | the scroll frame size is not what the mock assumes | a screenshot |
| a name in the report | a debug section prints a name | the section title (not the name) |
| *Last errors* is empty after an error | the error handler was replaced by another addon after login | the other addon's name |
